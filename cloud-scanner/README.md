# Облачный сканер безопасности Yandex Cloud (Python)

Модуль проверяет ресурсы **Yandex Cloud** через публичный HTTP API. Установка CLI `yc` не требуется. Данные в облаке не изменяются, результат выводится в консоль и сохраняется в PostgreSQL.

## Состав

- `scanner.py` — основной исполняемый файл
- `Dockerfile` — сборка Docker-образа
- `docker-compose.yml` — связка scanner + PostgreSQL
- `requirements.txt` — зависимости с зафиксированными версиями
- `.env.example` — шаблон переменных окружения
- `.github/workflows/ci.yml` — CI/CD пайплайн с проверками безопасности

## Проверки по виртуальным машинам

Для каждой ВМ в указанном каталоге облака выполняется обзор:

1. Сервисный аккаунт ВМ и роли этого аккаунта на уровне облака и каталога
2. Наличие публичного IPv4 (one-to-one NAT)
3. Правила привязанных групп безопасности: чувствительные входящие порты с источником 0.0.0.0/0, признак «широких» правил, исходящие правила на 0.0.0.0/0
4. Снимки дисков ВМ: наличие, статус, возраст, использование ключа KMS для шифрования снимка
5. Метаданные экземпляра (поле user-data): эвристический поиск возможных секретов
6. Параметры доступа к метаданным (режим IMDSv2)
7. Тип загрузочного диска (SSD или HDD)
8. Сопоставление образа ОС со списком устаревших идентификаторов продуктов

Результаты сканирования сохраняются в PostgreSQL для аудита и отслеживания изменений.

Запросы к API при временных сбоях повторяются до трёх раз с увеличивающейся задержкой (библиотека `tenacity`). Пагинация обрабатывается автоматически.

## Условия эксплуатации

- Интерпретатор Python версии 3.10 или выше
- Исходящие HTTPS-запросы к узлам домена `api.cloud.yandex.net`
- Действующий IAM-токен и идентификаторы облака и каталога
- Docker и Docker Compose (для контейнеризированного запуска)

## Быстрый старт (Docker Compose)

```bash
# Клонирование репозитория
git clone https://gitlab.com/ccaf0942/python/-/tree/main/cloud-scanner
cd cloud-scanner

# Создание .env с секретами
cp .env.example .env
nano .env  # заполнить YC_TOKEN, FOLDER_ID, CLOUD_ID

# Запуск сканера + PostgreSQL
docker compose up --build
```

## Локальный запуск (без Docker)

Перейдите в каталог модуля (каталог, где расположены `scanner.py` и `requirements.txt`). Создайте виртуальное окружение и установите зависимости:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Отредактируйте `.env`. Обязательные поля:

    YC_TOKEN=
    FOLDER_ID=
    CLOUD_ID=

Запуск сканирования:

    python scanner.py

В среде Microsoft Windows активация окружения: `.venv\Scripts\activate` вместо строки с `source` или `. .venv/bin/activate`.

## Просмотр результатов в БД

Для просмотра сохранённых результатов сканирования:

    docker compose up -d db
    docker compose exec db psql -U postgres -d scanner -c "SELECT * FROM scan_results;"

## CI/CD

Пайплайн запускается при пуше в `master`. Этапы проверки:

|          Этап         |  Инструмент |               Назначение                      |
|-----------------------|-------------|-----------------------------------------------|
| Сканирование секретов | Gitleaks    | Поиск токенов и ключей в истории коммитов     |
| SAST                  | Bandit      | Статический анализ Python-кода на уязвимости  |
| Аудит зависимостей    | pip-audit   | Проверка зависимостей на известные CVE        |
| Линтер                | Flake8      | Проверка стиля кода (PEP 8)                   |
| Сборка                | Docker      | Сборка Docker-образа                          |
| Сканирование образа   | Trivy       | Поиск CRITICAL-уязвимостей в собранном образе |
| Публикация            | Docker Push | Пуш образа в Yandex Container Registry        |

## Зависимости проекта

Пакеты: `requests`, `python-dotenv`, `tenacity`, `psycopg2-binary`. Точные версии указаны в `requirements.txt`.

## Ограничения и ответственность

Файл `.env` с секретами не должен попадать в систему контроля версий. При недействительном токене или недостаточных правах скрипт завершится ошибкой при обращении к API. Анализ user-data носит эвристический характер; возможны как пропуски, так и ложные срабатывания. Инструмент не заменяет регламентированный аудит информационной безопасности. Сканер работает в режиме read-only, данные в облаке не изменяются.
